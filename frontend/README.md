# ExpoSlides Studio

React + TypeScript интерфейс локального дизайнера. Три страницы:

- **Загрузка:** PPTX-шаблон, текст или TXT, число слайдов и одна кнопка создания.
- **Результат:** крупный предпросмотр, миниатюры, переключение слайдов и скачивание PPTX/PDF.
  Доступные варианты выбираются в компактном списке.
- **История:** сохранённые презентации текущего браузера, дата и статус.

Планирование и сборка выполняются автоматически на сервере после одного нажатия.
Отдельных экранов плана, аудита, профиля шаблона, технических режимов и расширенных
настроек в основном интерфейсе нет. При старом задании, остановившемся на готовом плане,
можно нажать «Продолжить создание» без открытия редактора плана.

Сервер: `exposlides/studio.py`. Сборка находится в `exposlides/studio_static`;
React, стили и системные шрифты используются локально, CDN не нужен.

```bash
cd frontend
npm ci
npm run typecheck
npm test
npm run build
```

Тесты работают без сети: проверяют API, восстановление состояния, доступные действия
и серверный рендер React. Браузерная проверка дополняет их, но не подтверждает всю
матрицу браузеров и ОС из ТЗ. Для установки зависимостей нужен npm-кеш или реестр.

## Данные и восстановление

PPTX — до 25 МБ. TXT — UTF-8, до 100 000 символов. Генерация использует настроенную
текстовую модель; при её недоступности сценарий не подменяется локальной имитацией.
Запущенная генерация продолжает работать без открытой вкладки. Её состояние и готовые
файлы восстанавливаются из истории. Временная ошибка связи не удаляет ссылку на работу.
Частично готовый результат позволяет скачать уже созданные файлы и показывает ошибку.

Список работ и скачивание защищены постоянной HttpOnly cookie владельца. После очистки
cookies прежняя история недоступна из этого браузера; чужие работы не выдаются.

## API

`POST /api/design/generate` принимает `{template_id, request}` и запускает единый
процесс от планирования до результата. Проверки фактов, лимит времени, очередь,
отмена и сохранение промежуточных результатов остаются на сервере.

Раздельные `/api/design/plan`, `/build` и `/fix` сохранены для совместимости API.
Расширенный DesignRequest с таблицами, обязательными тезисами и параметрами моделей
по-прежнему доступен программно; эти элементы не загружают основной интерфейс.
