# ExpoSlides

Цифровой дизайнер презентаций: **PPTX-шаблон + материалы → план истории → три варианта
верстки → аудит и выбранные исправления → PPTX, PDF, HTML**.

Новая студия использует React/TypeScript и локальный Python-сервер. Один образец слайда
можно использовать многократно. Текст, таблицы, диаграммы, пиктограммы и схемы остаются
редактируемыми объектами PowerPoint. Фирменные элементы сохраняются из шаблона.

Инструкции планировщика в `prompts/designer/story.md` сохраняют на слайдах
основную мысль и её содержательные пояснения. Ориентир — 50–85 слов при достаточном
исходном материале и вместимости макета; короткие источники не дополняются ради объёма.
Планировщик получает приблизительную вместимость текстовых областей шаблона.
Заметки дополняют видимый текст. Проверка отклоняет чрезмерно сокращённые богатые
разделы даже при полном тексте в notes; это эвристика, а не доказательство смысловой
полноты. Факты и переполнение проверяются отдельно, до сборки и публикации.

При сборке дизайнер проверяет контраст заголовков, текста и номеров страниц с фоном
слайда и лежащими под ними фигурами. Нечитаемый цвет заменяется цветом из палитры
шаблона (либо чёрным/белым) с контрастом не ниже 4.5:1. Для фотографий, сложных
заливок и фона, который нельзя однозначно определить, добавляется белая подложка.
Проверка применяется также к заполненным исходным текстовым фигурам; читаемые
цвета сохраняются. Исходный файл шаблона не изменяется.

## Быстрый запуск

Нужны Python 3.12, uv, LibreOffice и Poppler. Для изменения интерфейса нужен Node.js 22+;
готовая сборка интерфейса хранится в репозитории.

```bash
uv python install 3.12
uv sync --locked
uv run python -m exposlides.studio
```

Откройте **http://127.0.0.1:8765**. Загрузите PPTX-шаблон, вставьте текст или выберите
TXT, укажите число слайдов и нажмите «Создать презентацию». Содержание и сборка
выполняются автоматически. На странице результата доступны предпросмотр и скачивание
PPTX/PDF; предыдущие работы находятся в истории. Для этого сценария нужна настроенная
текстовая модель. Проверочный режим без модели остаётся доступен в CLI/API.

Установка конвертеров на macOS:

```bash
brew install --cask libreoffice
brew install poppler
```

Ubuntu/Debian:

```bash
sudo apt install libreoffice poppler-utils
```

На Windows установите LibreOffice и Poppler, добавьте soffice.exe, pdftoppm.exe
и pdftocairo.exe в PATH. pdftocairo обеспечивает векторное представление слайдов
в HTML; при его отсутствии HTML содержит PNG и отдельный доступный текст/таблицы.
Без LibreOffice или pdftoppm новый сценарий экспорта выдаёт ошибку.

Другой порт и каталог файлов:

```bash
uv run python -m exposlides.studio --port 8766 --data-dir ./local-studio
```

По умолчанию данные сохраняются в ~/.local/share/exposlides/studio: задания,
шаблоны, материалы, версии результатов и аудит. После перезапуска завершённые задания
восстанавливаются; прерванные помечаются ошибкой, а уже опубликованные варианты остаются
доступны для скачивания. Ключи в этих результатах не сохраняются.
Каталог содержит пользовательские материалы: храните его вне публичного репозитория.

Планирование, сборка и исправления разделяют общий лимит восьми активных заданий.
Если очередь заполнена, запуск отклоняется без изменения проверяемого плана или
готового результата. Можно повторить действие после завершения другой работы;
отмена освобождает место после подтверждения остановки.

## Настройка моделей

Скопируйте пример, если собственного файла конфигурации ещё нет:

```bash
cp -n .env.example services/content-service/.env
```

На Windows используйте копирование без перезаписи существующего файла.
Ключ задаётся локально через LLM_API_KEY. Новый дизайнер проверяет выбранную модель
по [реестру](config/models.toml).

| Переменная | Назначение |
| --- | --- |
| LLM_BASE_URL | OpenAI-compatible адрес инференса |
| LLM_API_KEY | Ключ провайдера, только в локальном окружении |
| LLM_MODEL | Обычный режим старого placeholder pipeline |
| LLM_FAST_MODEL | История и контекстуальный аудит новой студии; для аудита endpoint должен принимать изображения |
| IMAGE_API_URL | По умолчанию HF/fal Z-Image-Turbo |
| IMAGE_API_KEY | Необязательный отдельный ключ; для штатного HF endpoint берётся LLM_API_KEY |
| IMAGE_MODEL | Tongyi-MAI/Z-Image-Turbo |
| IMAGE_GENERATION_ENABLED | true в окружении процесса Studio включает иллюстрации в областях фото выбранных макетов |
| LOG_LEVEL | INFO; DEBUG может записывать исходные материалы и ответы |

Для финала топ-10 требуется инференс VK. Адрес и точный alias выдаёт организатор;
подтверждённый alias нужно внести в реестр модели. Автоматической подмены модели нет.
VK/VLM endpoint отдельно не проверялся. HF/fal Z-Image-Turbo проверен реальным запросом
28 сентября 2026: изображение вставлено в PPTX, файл повторно открыт.


Пояснения исходного выступления сохраняются в заметках докладчика. Проверка полноты
учитывает их вместе с краткими тезисами, но требует видимого содержания каждого
источника; числа и обязательные сообщения должны оставаться на слайдах. Исправление
полноты не дописывает стенограмму к тезисам. Вместимость основного текста проверяется
для всех трёх вариантов до сборки; при переполнении планировщик получает ограниченную
попытку исправления. Это геометрическая оценка, а не замена визуальной проверки PPTX.

Контекстуальный аудит включается явно. При IMAGE_GENERATION_ENABLED=true сначала
выбираются исходные композиции шаблона. Иллюстрация создаётся только для слайдов,
где хотя бы один вариант использует макет с заменяемыми фотографиями;
изображение заполняет исходные области фото, с сохранением масок, порядка фигур
и текстовых блоков. Кадрирование центральное, без растяжения. Несколько областей
одного слайда используют его общую иллюстрацию.
Текстовые макеты остаются текстовыми, автоиллюстрации не перестраивают их композицию.
Обложка исключена, кроме презентации из одного слайда. Для выбранных слайдов
используются отдельные сюжеты и seed. Запросы выполняются
параллельно, не более трёх одновременно; весь набор ограничен 90 секундами и остатком
общего бюджета с резервом 30 секунд на сборку. Набор переиспользуется в трёх вариантах.
Крупные фото на слайдах и в их layout заменяются, включая фигурные маски.
Для каждого слайда создаётся независимая копия layout/master, чтобы его фото
не меняло соседние слайды. Логотипы, мелкий декор, фон и изображения master сохраняются. Распознавание основано на имени и
геометрии, поэтому необычно оформленные логотипы следует явно назвать Logo/Логотип.
Если набор неполон, повреждён или содержит идентичные картинки, результат не публикуется
под видом успешно сгенерированного набора.
Текст остаётся редактируемым. generated_image.auto=false в запросе отключает автоматический
выбор; явные enabled/prompt/slide_id позволяют задать сюжет и слайд. LLM сначала составляет
визуальный сюжет без текста, затем вызывается Z-Image. Оба API используют один HF-ключ.
Модель 6B, Apache-2.0; отдельная GPU не нужна. Общий deadline и отмена pipeline сохраняются.
Индикатор настроенности означает
наличие конфигурации, а не успешный тест удалённого провайдера. При выключенном или
неудачном аудите результат содержит not_run или failed, а не ложное заключение.
Если текстовая модель не настроена, студия блокирует создание презентации до исправления
конфигурации. После настройки обновите страницу: готовность проверяется заново.
Исходные материалы сохраняются в форме; режим не переключается автоматически.
Ошибки доступа, соединения, таймаута, формата ответа и проверки фактов показываются
отдельно; ключи, адрес провайдера и его сырой ответ в сообщение не попадают.
Подробности, лицензии и ограничения: [MODELS.md](MODELS.md).

## Материалы и шаблоны

- Загрузите PPTX до 25 МБ. Поддерживаются placeholders и обычные текстовые поля,
  группы, несколько masters/layouts и собственные темы слайдов. Шаблоны с произвольными
  показами или разделами отклоняются при загрузке; их нужно удалить в копии шаблона,
  поскольку безопасный перенос этих ссылок в новую колоду пока не поддерживается.
- Вставьте текст или импортируйте UTF-8 TXT. Разделяйте самостоятельные темы пустой строкой.
- В поле «Добавить таблицы» выберите один или несколько CSV/TSV в UTF-8:
  файлы добавляются сразу, без заполнения дополнительных полей. Название и источник
  берутся из имени файла. Единицы при необходимости указывайте в заголовках столбцов.
  В интерфейсе оставлено одно поле «Добавить таблицы» для загрузки CSV/TSV.
  Первый столбец — подписи, остальные — числа. До 20 таблиц и 20 столбцов в каждой,
  без ограничения числа строк. Размер каждого файла — до 400 КБ. В интерфейсе отображаются имена файлов; в генерацию передаются все строки. CSV разделяется запятой или «;»;
  десятичная запятая допустима при разделителе «;» или табуляции. Пустые значения
  не заменяются нулями. Планировщик выбирает визуализацию по смыслу; использование
  каждого набора не гарантируется. Дробные числа сохраняются без дополнительного
  округления. Вариант «Доказательства» заменяет график таблицей только при достаточном
  месте; иначе сохраняет график со всеми данными. Явно запрошенная таблица, которая
  не помещается, отклоняется до сборки с предложением разделить данные или выбрать график.
  Прямой импорт XLSX и извлечение чисел из свободного текста пока не поддерживаются.
  CLI/API также принимают datasets в JSON-запросе.
- Перед автоматической сборкой проверяются факты, ссылки, полнота и число слайдов.
  Цель, аудитория и дополнительная модельная проверка задаются через CLI/API.
  Раздельное создание плана доступно через API; сохранённый план можно редактировать в студии.
  В результате блок «Проверка качества» показывает замечания, области на слайдах
  и выбор безопасных исправлений. Исправления создают новую версию; прежние экспорты доступны.
- Варианты используют одну историю и выбирают подходящие композиции из загруженного
  шаблона. Текст заполняет существующие фигуры: сохраняются их расположение, заливки,
  шрифты, маркеры и отступы. Цветные номера и декоративные элементы остаются на месте.
  Планировщик получает бюджет текста для обложки, если в шаблоне есть пригодный
  титульный макет. Выбор учитывает уже использованные композиции и сохраняет
  фотографии; разнообразие не имеет приоритета над вместимостью текста.
  Планировщик также получает число смысловых блоков подходящих композиций, чтобы
  карточки и списки не оставались полупустыми. Образцы не передают модели свои тексты.
  Заполненный макет предпочтительнее полупустого; среди пригодных чередуются текст,
  несколько блоков и композиции с фото, внутри каждого типа — новые композиции;
  номер образца больше не имеет приоритета над оценкой пригодности. Подсказки по числу
  блоков выбираются из всего каталога без дубликатов, включая поздние карточки и колонки.
  При необходимом повторе меняется соседство, чтобы не воспроизводить короткий цикл.
  Если подходящих композиций недостаточно для трёх различимых колод, сборка сообщает
  об ограничении. Искусственная перестройка текстовых блоков ради различий не выполняется. Три последовательных
  повтора одного макета и геометрии отмечаются предупреждением repeated_layout,
  даже когда содержание различается. Циклы из двух–четырёх макетов отмечаются
  предупреждением layout_cycle.

Для автоматического запуска используйте конфигурацию DesignRequest в JSON:

```json
{
  "script": "Исходные материалы с фактами и выводами.",
  "purpose": "Обосновать решение",
  "audience": "Команда продукта",
  "slide_count": 12,
  "count_mode": "exact",
  "mode": "llm",
  "contextual_audit": false,
  "required_messages": [],
  "datasets": []
}
```

```bash
uv run python -m exposlides.design_cli \
  --template /path/to/template.pptx \
  --request /path/to/request.json \
  --output-dir /path/to/new-result-directory
```

Или офлайн, без генерации новых формулировок:

```bash
uv run python -m exposlides.design_cli \
  --template /path/to/template.pptx \
  --script /path/to/script.txt \
  --mode extractive --slides 12 \
  --output-dir /path/to/new-result-directory
```

Каталог результата должен быть новым или пустым. В нём находятся manifest.json,
profile.json, story.json, result.json и variants/<вариант>/<версия>/ с PPTX,
PDF, HTML, кадрами, планом верстки и аудитом. Manifest хранит версии и хеши
промптов/ролей/реестра, хеш шаблона, исходного текста и полного request.json,
включая таблицы данных и настройки генерации. Для LLM-плана поле story_model содержит
модель, использованный alias endpoint и происхождение промпта из адаптера;
в проверочном режиме оно равно null. Полный запрос сохраняется в request.json.
Ключи туда не попадают.
Ограничение — 300 секунд на планирование и сборку всех трёх вариантов;
ожидание проверки плана пользователем не учитывается. Это ограничитель времени,
а не подтверждённая гарантия скорости внешнего инференса.

Полный запуск одним конфигом: скопируйте [config/run.example.toml](config/run.example.toml),
укажите пути к материалам и выполните:

```bash
uv run python -m exposlides.run_config /path/to/run.toml
```

Пути разрешаются относительно TOML. Секреты задаются отдельно через окружение.
Пороги аудита и версии программных навыков вынесены в [config/skills.toml](config/skills.toml)
и включаются в manifest. После изменения конфигов перезапустите сервер.

## Аудит и исправления

Геометрические и структурные проверки выполняются после сборки, включая повторное
открытие PPTX. Замечания привязаны к слайдам и областям. Пользователь выбирает
исправления; для выбранного варианта создаётся новая версия из выбранной исходной.
Она проходит повторный аудит, предыдущая остаётся доступной.

Перед повторной сборкой сохранённый профиль обновляется из результата разбора
шаблона, чтобы старые ошибочные текстовые слоты не попадали в новые варианты.
Несовпадение шаблона с контрольной суммой профиля останавливает сборку.

Автоматически исправляются ограниченные безопасные случаи: положение за краем,
вместимость текста при читаемом кегле и цвет из палитры. Для замечаний без безопасного
исправления отображается необходимость ручной правки.
Матрица проверок и ограничений: [AUDIT.md](AUDIT.md).

## Разработка и проверки

```bash
uv run pytest
uv run ruff check .
uv lock --check
uv run python scripts/test_services.py
```

Автоматические тесты используют подмену LLM и не требуют API-ключей. Сервисный
runner создаёт временные protobuf-модули и запускает изолированные тесты;
он не поднимает настоящий Kafka/Redis/MinIO-контур.

```bash
cd frontend
npm ci
npm test
npm run build
```

Сборка обновляет exposlides/studio_static/. React и стили обслуживаются локально;
CDN не нужен. Сборку нужно обновлять вместе с исходниками.
[Устройство интерфейса](frontend/README.md).

## Границы реализации

Распознавание шаблона эвристическое. Фоновые изображения, необычные композиции
и шрифты требуют визуальной проверки. Вместимость текста оценивается по геометрии,
а не по измерению каждого глифа. Корпоративные шрифты должны быть установлены
в среде конвертера.

Нативный SmartArt изменяется при наличии совместимого образца в шаблоне:
число узлов и связи должны совпадать. Произвольное создание всех типов SmartArt
не поддерживается. Process/comparison создаются отдельными редактируемыми фигурами.
Шаблоны с custom shows и sections принимаются. В новой колоде удаляются исходные
списки показов, разделы и переходы к этим показам; показ охватывает все созданные слайды.
Загруженный оригинал сохраняется без изменений. Внутренняя ссылка на слайд,
который не включён в результат, приводит к ошибке. Новая колода статическая:
тайминги анимации удаляются при клонировании.

Студия предназначена для локального рабочего места и слушает 127.0.0.1; она не
заменяет многопользовательскую аутентификацию. Отдельные сетевые сервисы существуют,
но новый designer workflow пока запускается файловыми этапами. Реальный сетевой
контур и матрица Chrome/Firefox/Safari/Яндекс на двух ОС не подтверждаются unit-тестами.

История, шаблоны и скачивание привязаны к постоянному HttpOnly-cookie браузера.
Другой браузер не видит эти работы. Удаление cookie прекращает доступ через интерфейс;
файлы остаются в каталоге данных. Это локальная изоляция, не система учётных записей.

Официальные конкурсные шаблоны, контент-пакет и неизвестный финальный шаблон
должны пройти отдельную приёмку. Синтетические fixtures не являются их заменой.

Старый сценарий подстановки текста остаётся доступен через python -m exposlides
и python -m exposlides.web. Его ограничение «один исходный слайд — один раз»
относится к старому builder; новая студия использует отдельный native builder.

## Иллюстрации предыдущего CLI/web

Следующие настройки относятся к `python -m exposlides` и `exposlides.web`.
Новая студия использует отдельную роль `image_illustrator`, описанную выше.


Общий CLI и веб-интерфейс автоматически используют **Tongyi-MAI/Z-Image-Turbo**
через HF/fal. Второй ключ не нужен: этап читает тот же `LLM_API_KEY` из окружения
или `services/content-service/.env`; окружение имеет приоритет. Нужен HF-токен с
разрешением Inference Providers и доступным балансом. Текст слайда и палитра
передаются HF/fal; исходные изображения шаблона не отправляются. Генерация оплачивается
по тарифу провайдера и не включена в стоимость текстового запроса.

Этап работает после сборки текста и до публикации PPTX. Выбираются PICTURE placeholders
и крупные неповторяющиеся непрозрачные изображения, занимающие 8–65% площади слайда
с пропорциями 0.4–2.5. Это эвристика, а не семантическое распознавание логотипов.
Для явного выбора переименуйте картинку в панели выделения PowerPoint, добавив
`exposlides:image`; для сохранения — `keep`. Имена с `logo`, `логотип`, `brand`,
`watermark`, `фон`, `background`, `keep` защищены и имеют приоритет над маркером генерации.
Группы, повёрнутые картинки, области вне слайда и области под непустым текстом пропускаются.
Непомеченные повторяющиеся картинки и прозрачные PNG также сохраняются.

Если подходящих областей нет, слайды собираются без новых картинок: свободное место
произвольно не заполняется. LLM сначала превращает текст готового слайда и палитру
в короткое описание визуальной сцены на английском. Генератор получает эту сцену
и пропорции области, без исходного текста слайда. Подписи, числа и графики в картинку
не запрашиваются. На область выполняется дополнительный короткий LLM-запрос. Изображение
кадрируется по центру без растягивания, затем вставляется отдельным объектом с сохранением
геометрии, слоя, рамки и ссылки. Результат повторно открывается и проверяется.
Точное воспроизведение художественного стиля и смысловую релевантность оценивайте визуально.

Настройки (уже имеют эти значения по умолчанию):

```dotenv
IMAGE_GENERATION_ENABLED=true
IMAGE_API_TIMEOUT=60
IMAGE_GENERATION_TIMEOUT=120
IMAGE_CONCURRENCY=2
IMAGE_MAX_COUNT=20
```

`IMAGE_GENERATION_TIMEOUT` ограничивает весь этап, включая очередь запросов.
Лимит относится к одной презентации; несколько веб-заданий могут работать параллельно.
Общий предел пяти минут для текста, картинок и рендера пока не гарантируется.
При ошибке API, неверном ключе, недостаточном балансе или превышении лимита изображений
результат не публикуется, существующий выходной PPTX сохраняется. Автоматически повторяется
только HTTP 429 (один раз); таймаут не повторяется, чтобы не дублировать возможную оплату.

Отключение: `--image-mode off` для CLI или `IMAGE_GENERATION_ENABLED=false` для CLI/web.
Перезапустите веб-сервер после изменения окружения процесса. В `--artifacts-dir`
сохраняется `image_report.json` со статусом, моделью, координатами и хешами картинок;
ключ и промпты в отчёт не входят. Прямой запуск `builder-service` сохраняет прежнее
поведение: этап изображений подключён в корневом pipeline.

Модель, API и ограничения ТЗ: [MODELS.md](MODELS.md).

### Три версии по нативным макетам

Дизайнер использует заполненные слайды и пригодные встроенные текстовые layouts всех
masters. Дополнительные образцы создаются только в рабочем `layout-template.pptx`;
загруженный оригинал сохраняется. Профиль и сборка связаны с этой копией по SHA-256.
Пустые placeholders для фото, диаграмм и других специальных объектов не превращаются
в готовые композиции. Геометрия, шрифты и маски выбранного макета сохраняются.

Для узких фото-макетов генератор получает рассчитанный по геометрии ориентир
длины заголовка; уточнения остаются в тезисах. Пустые большие панели не используются
как готовые иллюстрации.
Короткий заголовок по возможности остаётся в одной строке: допустимое уменьшение
кегля и подходящий широкий макет имеют приоритет перед разнообразием. У обычного
текста без маркера убирается унаследованный выступ: продолжение начинается на той
же вертикали, что первая строка. Отступы настоящих списков сохраняются.

Ось различий трёх версий — выбор и последовательность нативных композиций, распределение
тезисов по предусмотренным областям. Другой номер исходного слайда сам по себе
различием не считается. Приоритет имеют вместимость текста и отсутствие пустых областей.
Перед сборкой попарно проверяются фактические композиции: каждая пара колод должна
различаться хотя бы одним слайдом. Обложка может быть общей, если различаются другие
слайды. Для однослайдовой презентации также выбираются разные подходящие композиции;
одинаковые обложки не засчитываются как три варианта. Отчёт сохраняется в
`variant-diversity.json`. Если шаблон и объём текста не позволяют выполнить условие,
сборка сообщает об этом вместо выдачи трёх одинаковых вариантов.


Если план студии после всех попыток исправления сохраняет ошибки фактов, чисел,
полноты или размещения, доступная презентация всё равно собирается. Над результатом
показывается предупреждение, подробности сохраняются в проверке качества каждого
варианта. Это не означает успешную проверку содержания. Некорректный JSON,
неизвестные ссылки на источники/таблицы и отсутствие плана остаются ошибками.
