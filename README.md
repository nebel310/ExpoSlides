# ExpoSlides

Сервис создания презентаций в фирменном стиле: **PPTX-шаблон + материалы → план
содержания → три варианта верстки → аудит и исправления → PPTX, PDF, HTML**.
Текст, таблицы, диаграммы и поддерживаемые схемы экспортируются редактируемыми
объектами PowerPoint. Интерфейс — React/TypeScript, сервер и pipeline — Python.

## Запуск

Команды выполняются из корня репозитория, если не указано другое.
Нужны **Python 3.12, uv, LibreOffice, Poppler** и шрифты шаблона.
При внешнем API-инференсе видеокарта не нужна. Node.js 22+ нужен только для разработки
интерфейса: готовая сборка уже находится в репозитории.

Установите конвертеры. На macOS:

```bash
brew install --cask libreoffice
brew install poppler
```

На Ubuntu/Debian:

```bash
sudo apt install libreoffice-impress poppler-utils fonts-liberation fonts-dejavu-core
```

На Windows установите LibreOffice и Poppler и добавьте каталоги с `soffice.exe`,
`pdftoppm.exe` и `pdftocairo.exe` в `PATH`. Команды с `export` и переносом `\`
ниже приведены для bash/zsh.

Установите зависимости:

```bash
uv python install 3.12
uv sync --locked
```

Настройте модель по следующему разделу, затем запустите студию:

```bash
uv run python -m exposlides.studio
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765).
Для остановки нажмите `Ctrl+C` в терминале. Другой порт и каталог хранения:

```bash
uv run python -m exposlides.studio --port 8766 --data-dir ./local-studio
```

Для студии не нужны Kafka, PostgreSQL, MinIO или Docker Compose.
Развёртывание действующего демо, обслуживание и откат — в
[инструкции сервера](deploy/alex-cloud/README.md).

## Настройка моделей

Создайте `services/content-service/.env`. Если файл уже существует, измените только
нужные параметры. Минимальная конфигурация для текущего профиля Hugging Face:

```dotenv
LLM_BASE_URL=https://router.huggingface.co/v1
LLM_API_KEY=your-hf-token
LLM_FAST_MODEL=Qwen/Qwen3.8-27B:deepinfra
LLM_FAST_API_TIMEOUT=180
LLM_REASONING_EFFORT=none
LOG_LEVEL=INFO
```

Замените `your-hf-token` токеном с разрешением Inference Providers и доступом к модели.
Окружение процесса имеет приоритет над `.env`. После изменений перезапустите студию
и обновите страницу. Ключи не добавляйте в Git, конфиги запуска и отчёты.
[.env.example](.env.example) содержит также настройки других сервисов и старого CLI;
для студии достаточно приведённого выше набора.

| Переменная | Назначение |
| --- | --- |
| `LLM_BASE_URL` | Адрес OpenAI-compatible API |
| `LLM_API_KEY` | Ключ провайдера |
| `LLM_FAST_MODEL` | Модель содержания и контекстуального аудита; alias проверяется по [реестру](config/models.toml) |
| `LLM_FAST_API_TIMEOUT` | Таймаут текстового запроса, по умолчанию 180 секунд; действует и общий бюджет задания |
| `LLM_REASONING_EFFORT` | Для текущего профиля — `none` |
| `LLM_MAX_TOKENS` | Максимальный размер ответа, по умолчанию 8192 |
| `LOG_LEVEL` | Обычно `INFO`; `DEBUG` может записывать материалы, промпты и ответы |
| `IMAGE_GENERATION_ENABLED` | `true` в окружении **процесса Studio/CLI** включает автоиллюстрации |
| `IMAGE_API_URL` | Endpoint изображений |
| `IMAGE_API_KEY` | Отдельный ключ; для штатного HF/fal при отсутствии используется `LLM_API_KEY` |
| `IMAGE_MODEL` | Для текущего иллюстратора — `Tongyi-MAI/Z-Image-Turbo` |
| `IMAGE_API_TIMEOUT` | Таймаут запроса изображения, по умолчанию 90 секунд |

Для автоиллюстраций добавьте в `.env`:

```dotenv
IMAGE_API_URL=https://router.huggingface.co/fal-ai/fal-ai/z-image/turbo
IMAGE_MODEL=Tongyi-MAI/Z-Image-Turbo
```

В `.env.example` уже указаны этот endpoint и модель.
Включите автоматический режим в окружении запуска:

```bash
export IMAGE_GENERATION_ENABLED=true
uv run python -m exposlides.studio
```

В PowerShell используйте `$env:IMAGE_GENERATION_ENABLED = "true"`, затем команду запуска.
Для отключения задайте `false`. Одного значения в `.env` content-service недостаточно.
В JSON/TOML `generated_image.auto=false` отключает автоматический выбор; явные
`enabled=true` и непустой `prompt` запрашивают отдельную иллюстрацию.

Генерация отправляет материалы настроенному провайдеру; контекстуальный аудит также
передаёт кадры слайдов. Иллюстратор получает описание сцены и палитру.
Стоимость зависит от провайдера. Индикатор готовности проверяет настройки,
но не подтверждает доступность удалённого API.

Для топ-10 по ТЗ обязателен инференс VK: нужны endpoint и точный alias организатора.
Подтверждённый alias внесите в реестр и настройте `LLM_BASE_URL`/`LLM_FAST_MODEL`.
Живой VK-инференс пока не проверен; работа через HF не является такой проверкой.
Модели, лицензии, ссылки на веса и ресурсы описаны в [MODELS.md](MODELS.md).

## Как пользоваться

1. **Загрузите PPTX-шаблон.** Несколько подходящих композиций — текст, колонки,
   карточки, фото — позволяют получить более различимые варианты. Оригинал сохраняется.
2. **Добавьте материалы:** вставьте текст или загрузите TXT в UTF-8. Разделяйте темы
   пустыми строками; указывайте факты, числа, единицы и выводы.
3. **При необходимости добавьте таблицы.** Поле «Добавить таблицы Excel/CSV»
   принимает CSV/TSV. Из Excel сначала сохраните CSV: прямого импорта XLSX нет.
4. **Укажите число слайдов** и нажмите «Создать презентацию».
   Планирование, сборка и первичный аудит выполняются автоматически.
5. **Сравните варианты 1–3.** При переключении сохраняется номер текущего слайда.
   Откройте «Проверку качества», посмотрите замечания и отмеченные области.
6. **Выберите доступные исправления.** Для выбранного варианта создаётся новая версия
   с повторным аудитом. Прежние версии доступны; часть замечаний требует ручной правки.
7. **Скачайте PPTX, PDF или HTML.** HTML автономный. В PPTX сохраняются заметки
   докладчика и редактируемые объекты.

Работы доступны в «Истории». Закрытие вкладки или переход к новой презентации
не останавливает генерацию, пока работает сервер. После перезапуска сервера готовые
файлы сохраняются, незавершённые задания помечаются ошибкой.
Для работы, остановившейся на готовом плане, доступны его редактирование и сборка.

## Материалы и ограничения входа

| Вход | Формат и лимиты |
| --- | --- |
| Шаблон | PPTX до 25 МиБ и 250 слайдов; placeholders, текстовые поля, группы, несколько masters/layouts |
| Материалы | Текст или UTF-8 TXT, до 100 000 символов |
| Число слайдов | 1–50, по умолчанию 12; целевой объём ТЗ — 10–15 |
| Данные | До 20 CSV/TSV по 400 КБ, до 20 столбцов; фиксированного лимита строк нет |

В CSV/TSV первая строка — заголовки, первый столбец — подписи, остальные — числа.
CSV поддерживает запятую или `;`; десятичная запятая допустима с `;` или табуляцией.
Название и источник берутся из имени файла. Единицы укажите в заголовках.
Пустые значения не подменяются нулями. Пример:

```csv
Квартал;Выручка, млн руб.
Первый;12,5
Второй;15,2
```

Все строки передаются планировщику, но использование каждого набора не гарантируется.
Таблица должна помещаться на слайд: большие наборы разделите или используйте график.
Импорт DOCX/PDF/XLSX и извлечение числовых рядов из свободного текста не реализованы.

## Запуск одним конфигом

Сохраните TOML по образцу [config/run.example.toml](config/run.example.toml).
Пути разрешаются относительно TOML. Каталог результата должен быть новым или пустым:

```toml
template = "./template.pptx"
script = "./script.txt"
output_dir = "./result-01"
timeout_seconds = 300

[generation]
purpose = "Обосновать решение"
audience = "Команда продукта"
slide_count = 12
count_mode = "exact"
mode = "llm"
language = "ru"
contextual_audit = false
required_messages = []

[generation.generated_image]
enabled = false
auto = false
```

```bash
uv run python -m exposlides.run_config /path/to/run.toml
```

`count_mode="exact"` задаёт точное число слайдов, `"maximum"` — верхнюю границу.
`required_messages` — обязательные тезисы. `contextual_audit=true` включает
модельную проверку кадров; endpoint должен поддерживать изображения.
Ключи остаются в `.env` или окружении.

Альтернатива — CLI:

```bash
uv run python -m exposlides.design_cli \
  --template /path/to/template.pptx \
  --script /path/to/script.txt \
  --mode llm --slides 12 \
  --output-dir /path/to/result-02
```

Вместо `--script` можно передать `--request /path/to/request.json` с объектом
[DesignRequest](exposlides/design_models.py), включая `datasets`.
В этом случае параметры содержания берутся из JSON.

Для проверки **без внешних моделей** используйте TOML выше с `mode="extractive"`,
`contextual_audit=false`, `generated_image.enabled=false`, `generated_image.auto=false`.
Режим распределяет исходные формулировки без LLM; конвертеры всё равно нужны.
Такой прогон проверяет сборку и экспорт, но не качество генерации модели.

### Результаты и хранение

В каталоге запуска находятся `request.json`, `profile.json`, `story.json`,
`story-validation.json`, `manifest.json`, `variant-diversity.json`, `result.json`
и `variants/<story|evidence|cards>/<версия>/` с PPTX, PDF, HTML, кадрами, планом и аудитом.
Manifest фиксирует модель, версии и хеши промптов, ролей, конфигов и входных материалов.
Повторный LLM-запрос не гарантирует побайтово одинаковый результат.

Студия хранит данные в `~/.local/share/exposlides/studio`, если не задан `--data-dir`.
История и скачивание привязаны к HttpOnly-cookie: удаление cookie прекращает доступ
к истории из интерфейса, файлы остаются на диске. Резервируйте весь каталог данных;
он содержит пользовательские материалы и результаты.

## Три варианта, аудит и исправления

**Ось различий — выбор и последовательность композиций шаблона, распределение тезисов
по его областям и представление данных.** История и факты общие. Это сохраняет фирменные
макеты и позволяет сравнивать оформление одного содержания. Образцы используются повторно.

Сравнивается фактическая геометрия: другой номер образца сам по себе не считается
отличием. Проверка сохраняется в `variant-diversity.json`. При недостатке композиций
LLM-режим может выдать похожие варианты с предупреждением; в `extractive` это ошибка.

- **Детерминированные проверки:** факты и ссылки по правилам, геометрия, вместимость,
  стили, палитра, плотность, дубли, нативность объектов и повторное открытие PPTX.
- **Контекстуальный аудит:** модель оценивает смысл и изображение слайда; включается
  отдельно. Статусы `not_run` и `failed` не означают успешную проверку.
- **Исправления:** пользователь выбирает поддерживаемые действия; новая версия
  проходит повторный аудит. Для остальных замечаний нужна ручная правка.

Сборка повторно разбирает PPTX, включая изображения внутри placeholders. Для каждой
фотообласти автоиллюстраций создаётся отдельный запрос; одна картинка не размножается
по нескольким областям. Повтор содержательной иллюстрации внутри готовой колоды
останавливает публикацию, включая одинаковые пиксели в PNG с разными метаданными.
Логотипы и фон исключены. При наличии подходящего вместимого макета соседняя
композиция не повторяется; малое число подходящих макетов ограничивает разнообразие.

Автоиллюстрации заполняют подходящие фотообласти макетов с сохранением масок
и пропорций. Варианты переиспользуют подготовленный набор. Текстовые макеты ради
картинок не перестраиваются. Защита логотипов эвристическая: необычный логотип
лучше явно назвать `Logo` или `Логотип`.

**Готовый файл не означает отсутствие ошибок.** После ограниченных попыток исправления
LLM-план с замечаниями фактов, полноты или размещения может быть собран с предупреждением.
Некорректный формат, отсутствующий план и неизвестные ссылки на источники/данные
останавливают генерацию. Перед использованием проверьте замечания и откройте PPTX.
Матрица проверок и тестов — в [AUDIT.md](AUDIT.md).

## Ограничения и частые ошибки

| Ситуация | Что сделать |
| --- | --- |
| Модель не настроена | Проверьте `.env`, ключ, URL и alias по реестру; перезапустите студию и обновите страницу |
| Ошибка доступа или лимита API | Проверьте разрешения токена, доступ к модели и лимиты провайдера |
| Ошибка PDF/предпросмотра | Проверьте LibreOffice, `pdftoppm` и шрифты шаблона |
| Похожие варианты или переполнение | Добавьте подходящие макеты, сократите текст или увеличьте число слайдов |
| Таймаут или очередь заполнена | Повторите после других работ; уменьшите объём или отключите необязательные модельные этапы |
| Порт занят | Используйте другой `--port` |
| Каталог результата непустой | Укажите новый `output_dir` |

Планирование и сборка ограничены 300 секундами; это ограничитель, а не гарантия
скорости внешнего API. Общий лимит — восемь активных заданий. При частичном сбое
уже опубликованные варианты доступны, но вся работа не считается завершённой.

Распознавание шаблона и вместимость текста эвристические. Сложные фоны, композиции
и шрифты требуют визуальной проверки. Без `pdftocairo` HTML содержит PNG вместо SVG
и отдельный доступный текст/таблицы. SmartArt изменяется только при наличии совместимого
образца; произвольные типы не создаются. Process/comparison — редактируемые фигуры.

Новая студия принимает шаблоны с custom shows и sections: в результате удаляются
исходные списки показов, разделы и переходы к ним. Тайминги анимации удаляются.
Ссылка на слайд, отсутствующий в результате, приводит к ошибке.

Студия слушает `127.0.0.1` и рассчитана на локальную работу. Cookie-изоляция
не заменяет учётные записи. Новый workflow использует файловые этапы.
Старые `python -m exposlides` и `exposlides.web` используют другой pipeline,
где один исходный слайд применяется только один раз.

Матрица актуальной и предыдущей версий Chrome, Firefox, Safari и Яндекс Браузера
на macOS/Windows, официальный контент-пакет, неизвестный финальный шаблон и скорость
на VK требуют отдельной приёмки; unit-тесты её не заменяют.

```bash
uv run pytest

```

Тесты подменяют внешние API. Сервисный runner изолирует одноимённые пакеты `app`

Промежуточная сдача: репозиторий с доступом для экспертов, полный прогон сервиса,
**три варианта одного контента на каждом из трёх шаблонов — девять презентаций**.
Видео без монтажных склеек или живое демо — до семи минут.

Финал: зафиксированная версия репозитория, запуск конфигом и три варианта
на неизвестном заранее шаблоне. Питч до семи минут: проблема → подход → архитектура
pipeline → живое демо → устройство аудита → выводы.
Соответствие ТЗ подтверждается прогонами на выданных материалах и VK-инференсе.
