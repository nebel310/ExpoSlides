# ExpoSlides

Цифровой дизайнер презентаций: **PPTX-шаблон + материалы → план истории → три варианта
верстки → аудит и выбранные исправления → PPTX, PDF, HTML**.

Новая студия использует React/TypeScript и локальный Python-сервер. Один образец слайда
можно использовать многократно. Текст, таблицы, диаграммы, пиктограммы и схемы остаются
редактируемыми объектами PowerPoint. Фирменные элементы сохраняются из шаблона.

## Быстрый запуск

Нужны Python 3.12, uv, LibreOffice и Poppler. Для изменения интерфейса нужен Node.js 22+;
готовая сборка интерфейса хранится в репозитории.

```bash
uv python install 3.12
uv sync --locked
uv run python -m exposlides.studio
```

Откройте **http://127.0.0.1:8765**. Нажмите «Открыть пример», выберите режим
«Проверочный · без модели», проверьте число слайдов и создайте план. После проверки
плана нажмите «Собрать три варианта». Проверочный режим распределяет исходный текст,
не вызывает модель и не заменяет оценку качества LLM.

Установка конвертеров на macOS:

```bash
brew install --cask libreoffice
brew install poppler
```

Ubuntu/Debian:

```bash
sudo apt install libreoffice poppler-utils
```

На Windows установите LibreOffice и Poppler, добавьте soffice.exe, pdftoppm.exe
и pdftocairo.exe в PATH. pdftocairo обеспечивает векторное представление слайдов
в HTML; при его отсутствии HTML содержит PNG и отдельный доступный текст/таблицы.
Без LibreOffice или pdftoppm новый сценарий экспорта выдаёт ошибку.

Другой порт и каталог файлов:

```bash
uv run python -m exposlides.studio --port 8766 --data-dir ./local-studio
```

По умолчанию данные сохраняются в ~/.local/share/exposlides/studio: задания,
шаблоны, материалы, версии результатов и аудит. После перезапуска завершённые задания
восстанавливаются; прерванные помечаются ошибкой. Ключи в этих результатах не сохраняются.
Каталог содержит пользовательские материалы: храните его вне публичного репозитория.

Планирование, сборка и исправления разделяют общий лимит восьми активных заданий.
Если очередь заполнена, запуск отклоняется без изменения проверяемого плана или
готового результата. Можно повторить действие после завершения другой работы;
отмена освобождает место после подтверждения остановки.

## Настройка моделей

Скопируйте пример, если собственного файла конфигурации ещё нет:

```bash
cp -n .env.example services/content-service/.env
```

На Windows используйте копирование без перезаписи существующего файла.
Ключ задаётся локально через LLM_API_KEY. Новый дизайнер проверяет выбранную модель
по [реестру](config/models.toml).

| Переменная | Назначение |
| --- | --- |
| LLM_BASE_URL | OpenAI-compatible адрес инференса |
| LLM_API_KEY | Ключ провайдера, только в локальном окружении |
| LLM_MODEL | Обычный режим старого placeholder pipeline |
| LLM_FAST_MODEL | История и контекстуальный аудит новой студии; для аудита endpoint должен принимать изображения |
| IMAGE_API_URL, IMAGE_API_KEY | Необязательный HF-compatible endpoint иллюстраций |
| IMAGE_MODEL | black-forest-labs/FLUX.1-schnell |
| LOG_LEVEL | INFO; DEBUG может записывать исходные материалы и ответы |

Для финала топ-10 требуется инференс VK. Адрес и точный alias выдаёт организатор;
подтверждённый alias нужно внести в реестр модели. Автоматической подмены модели нет.
Код адаптеров проверен с подменой ответов; доступность и задержка реального
VK/VLM/image endpoint в этой доработке не проверялись.

Контекстуальный аудит и иллюстрации включаются явно. Индикатор настроенности означает
наличие конфигурации, а не успешный тест удалённого провайдера. При выключенном или
неудачном аудите результат содержит not_run или failed, а не ложное заключение.
Подробности, лицензии и ограничения: [MODELS.md](MODELS.md).

## Материалы и шаблоны

- Загрузите PPTX до 25 МБ. Поддерживаются placeholders и обычные текстовые поля,
  группы, несколько masters/layouts и собственные темы слайдов.
- Вставьте текст или импортируйте UTF-8 TXT. Разделяйте самостоятельные темы пустой строкой.
- Импортируйте JSON контент-пакет либо CSV для графиков. Числа передаются явно,
  вместе с источником и единицами; модель не должна придумывать значения.
- В плане можно менять заголовки, формулировки, порядок и представление данных.
  Перед сборкой повторно проверяются факты, ссылки, полнота и число слайдов.
- Три композиции — рассказ, доказательства и карточки — используют одну историю.
  Различаются расположение блоков и способ визуализации данных.

Для автоматического запуска используйте конфигурацию DesignRequest в JSON:

```json
{
  "script": "Исходные материалы с фактами и выводами.",
  "purpose": "Обосновать решение",
  "audience": "Команда продукта",
  "slide_count": 12,
  "count_mode": "exact",
  "mode": "llm",
  "contextual_audit": false,
  "required_messages": [],
  "datasets": []
}
```

```bash
uv run python -m exposlides.design_cli \
  --template /path/to/template.pptx \
  --request /path/to/request.json \
  --output-dir /path/to/new-result-directory
```

Или офлайн, без генерации новых формулировок:

```bash
uv run python -m exposlides.design_cli \
  --template /path/to/template.pptx \
  --script /path/to/script.txt \
  --mode extractive --slides 12 \
  --output-dir /path/to/new-result-directory
```

Каталог результата должен быть новым или пустым. В нём находятся manifest.json,
profile.json, story.json, result.json и variants/<вариант>/<версия>/ с PPTX,
PDF, HTML, кадрами, планом верстки и аудитом. Manifest хранит версии и хеши
промптов/ролей/реестра, хеш шаблона, исходного текста и полного request.json,
включая таблицы данных и настройки генерации. Для LLM-плана поле story_model содержит
модель, использованный alias endpoint и происхождение промпта из адаптера;
в проверочном режиме оно равно null. Полный запрос сохраняется в request.json.
Ключи туда не попадают.
Ограничение — 300 секунд на планирование и сборку всех трёх вариантов;
ожидание проверки плана пользователем не учитывается. Это ограничитель времени,
а не подтверждённая гарантия скорости внешнего инференса.

Полный запуск одним конфигом: скопируйте [config/run.example.toml](config/run.example.toml),
укажите пути к материалам и выполните:

```bash
uv run python -m exposlides.run_config /path/to/run.toml
```

Пути разрешаются относительно TOML. Секреты задаются отдельно через окружение.
Пороги аудита и версии программных навыков вынесены в [config/skills.toml](config/skills.toml)
и включаются в manifest. После изменения конфигов перезапустите сервер.

## Аудит и исправления

Геометрические и структурные проверки выполняются после сборки, включая повторное
открытие PPTX. Замечания привязаны к слайдам и областям. Пользователь выбирает
исправления; для выбранного варианта создаётся новая версия из выбранной исходной.
Она проходит повторный аудит, предыдущая остаётся доступной.

Автоматически исправляются ограниченные безопасные случаи: положение за краем,
вместимость текста при читаемом кегле и цвет из палитры. Для замечаний без безопасного
исправления отображается необходимость ручной правки.
Матрица проверок и ограничений: [AUDIT.md](AUDIT.md).

## Разработка и проверки

```bash
uv run pytest
uv run ruff check .
uv lock --check
uv run python scripts/test_services.py
```

Автоматические тесты используют подмену LLM и не требуют API-ключей. Сервисный
runner создаёт временные protobuf-модули и запускает изолированные тесты;
он не поднимает настоящий Kafka/Redis/MinIO-контур.

```bash
cd frontend
npm ci
npm test
npm run build
```

Сборка обновляет exposlides/studio_static/. React и стили обслуживаются локально;
CDN не нужен. Сборку нужно обновлять вместе с исходниками.
[Формат контент-пакета и интерфейс](frontend/README.md).

## Границы реализации

Распознавание шаблона эвристическое. Фоновые изображения, необычные композиции
и шрифты требуют визуальной проверки. Вместимость текста оценивается по геометрии,
а не по измерению каждого глифа. Корпоративные шрифты должны быть установлены
в среде конвертера.

Нативный SmartArt изменяется при наличии совместимого образца в шаблоне:
число узлов и связи должны совпадать. Произвольное создание всех типов SmartArt
не поддерживается. Process/comparison создаются отдельными редактируемыми фигурами.
Шаблоны с custom shows или sections отклоняются явно. Внутренняя ссылка на слайд,
который не включён в результат, также приводит к ошибке. Новая колода статическая:
тайминги анимации удаляются при клонировании.

Студия предназначена для локального рабочего места и слушает 127.0.0.1; она не
заменяет многопользовательскую аутентификацию. Отдельные сетевые сервисы существуют,
но новый designer workflow пока запускается файловыми этапами. Реальный сетевой
контур и матрица Chrome/Firefox/Safari/Яндекс на двух ОС не подтверждаются unit-тестами.

История, шаблоны и скачивание привязаны к постоянному HttpOnly-cookie браузера.
Другой браузер не видит эти работы. Удаление cookie прекращает доступ через интерфейс;
файлы остаются в каталоге данных. Это локальная изоляция, не система учётных записей.

Официальные конкурсные шаблоны, контент-пакет и неизвестный финальный шаблон
должны пройти отдельную приёмку. Синтетические fixtures не являются их заменой.

Старый сценарий подстановки текста остаётся доступен через python -m exposlides
и python -m exposlides.web. Его ограничение «один исходный слайд — один раз»
относится к старому builder; новая студия использует отдельный native builder.
