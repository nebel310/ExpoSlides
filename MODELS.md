# Модели и воспроизводимость

Состояние: 29 сентября 2026 года. Этот документ описывает новый workflow дизайнера.
Предыдущий текстовый pipeline остаётся доступным и имеет собственные настройки
повторов. Проверенный реестр нового workflow — [config/models.toml](config/models.toml),
роли и лимиты — [agents/designer.toml](agents/designer.toml), версии навыков и
пороги детерминированного аудита — [config/skills.toml](config/skills.toml).

## Выбор моделей

| Роль | Модель | Размер по карточке | Лицензия | Использование в коде |
| --- | --- | --- | --- | --- |
| Содержание | Qwen/Qwen3.8-27B | 27B | Apache-2.0 | `app.design_main`: структурированный ContentPlan |
| Контекстуальный аудит | Та же Qwen/Qwen3.8-27B | 27B | Apache-2.0 | `app.design_audit`: текст источника и изображение готового слайда |
| Необязательные иллюстрации | Tongyi-MAI/Z-Image-Turbo | 6B | Apache-2.0 | `app.design_image`, `app.design_images`: сюжет и палитра → PNG/JPEG |

Официальная [карточка Qwen](https://huggingface.co/Qwen/Qwen3.8-27B) публикует веса,
лицензию и примеры обработки изображений. Поддержка изображений самой моделью не
означает, что произвольный endpoint предоставляет этот режим: это проверяется
отдельным интеграционным запуском.

Текущая роль иллюстратора использует
[Tongyi-MAI/Z-Image-Turbo](https://huggingface.co/Tongyi-MAI/Z-Image-Turbo):
реестр фиксирует 6B, Apache-2.0 и лимит image-моделей 20B. Для штатного HF/fal
маршрута сначала Qwen составляет визуальный сюжет, затем Z-Image создаёт иллюстрацию
за восемь шагов. Локальная видеокарта для API-инференса не требуется.

[FLUX.1-schnell](https://huggingface.co/black-forest-labs/FLUX.1-schnell), 12B,
Apache-2.0, остаётся в реестре, но текущей роли не назначена. Её использование
требует явного изменения роли и подходящего endpoint; автоматической замены нет.
FLUX.1-dev и FLUX.1-pro в проверенный реестр не включены.

В ТЗ для прошедших в топ-10 обязателен инференс VK с Qwen 3.8 27b. Для этого
настраиваются выданные VK URL, ключ и точный идентификатор модели. Адрес VK нельзя
угадать: в репозитории его нет, работа с ним не подтверждена. Новый alias добавляется
в `endpoint_aliases` после проверки соответствия той же модели. Реестр проверяет
декларацию конфигурации, а не фактические веса на удалённом сервере.

## Настройки текстового и мультимодального API

Настройки читает `services/content-service/app/config.py`: переменные окружения
и `.env` относительно рабочего каталога content-service. Значения по умолчанию:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `LLM_API_KEY` | пусто | Bearer-ключ провайдера |
| `LLM_BASE_URL` | `https://router.huggingface.co/v1` | Базовый URL Chat Completions |
| `LLM_MODEL` | `Qwen/Qwen3.8-27B:deepinfra` | Модель предыдущего standard pipeline |
| `LLM_FAST_MODEL` | `Qwen/Qwen3.8-27B:deepinfra` | Новый планировщик и контекстуальный аудит; также fast pipeline |
| `LLM_FAST_REPAIR_MODEL` | `Qwen/Qwen3.8-27B:deepinfra` | Исправления предыдущего fast pipeline |
| `LLM_API_TIMEOUT` | 180 | Таймаут standard транспорта, секунды |
| `LLM_FAST_API_TIMEOUT` | 180 | Таймаут отдельного fast запроса, секунды |
| `FAST_GENERATION_TIMEOUT` | 240 | Общий бюджет предыдущего fast графа |
| `LLM_TEMPERATURE` | 0.2 | Температура Chat Completions |
| `LLM_MAX_TOKENS` | 8192 | Ограничение ответа Chat Completions |
| `LLM_REASONING_EFFORT` | `none` | Передаётся Hugging Face router |
| `LLM_RESPONSE_RETRIES` | 2 | Повторы предыдущего standard pipeline |
| `CONTENT_VALIDATION_RETRIES` | 2 | Повторы проверки предыдущего standard графа |

HTTP-транспорт проверяет TLS. Для Hugging Face ключ должен начинаться с `hf_` и
иметь разрешение Inference Providers. Для другого совместимого API используется
его ключ. Проект не переключается незаметно на другую модель при ошибке.

У нового дизайнера отдельные ограничения из `agents/designer.toml`: до трёх попыток
плана в пределах 240 секунд; до двух структурированных ответов на слайд для
контекстуального аудита, максимум три параллельных проверки и 120 секунд на весь
запрос аудита. Общий бюджет файлового pipeline дополнительно ограничивает этапы.
При сборке вариантов контекстуальная проверка каждого варианта ограничена 45
секундами и оставшимся временем общего бюджета.
Таймаут ограничивает ожидание и не гарантирует успешную генерацию за это время.

## Режимы

- `DesignRequest.mode="llm"` вызывает Qwen и проверяет структуру, источники,
  количество слайдов и содержание перед версткой.
- `mode="extractive"` работает локально: переносит материал из источника без
  вызова модели. Это явный режим, не скрытая подмена LLM после ошибки.
- `contextual_audit=false` оставляет статус `not_run`. При явном включении адаптер
  отправляет изображения через настроенный Chat Completions API. Публичная
  проверка готовности оценивает конфигурацию и реестр моделей; поддержку изображений
  конкретным endpoint подтверждают отдельным интеграционным запуском.
- `generated_image.enabled=true` включает явно заданную иллюстрацию. При
  `enabled=false`, `auto=true` и `IMAGE_GENERATION_ENABLED=true` в процессе студии
  иллюстрации создаются для подходящих областей фото выбранных макетов.
  `auto=false` отключает этот автоматический выбор. Изображения не заменяют
  таблицы и графики исходных данных.

Проверка фактов распространяется и на заметки докладчика. Пояснения в заметках
учитываются при проверке полноты вместе с видимыми тезисами. Каждый источник
должен иметь видимое содержание; числа и обязательные сообщения остаются на слайдах.

Сервисные entry points из каталога `services/content-service`:

```bash
uv run python -m app.design_main --request /absolute/request.json --output /absolute/story.json
uv run python -m app.design_audit --request /absolute/audit-request.json --output /absolute/audit.json
uv run python -m app.design_image --request /absolute/image-request.json --output /absolute/image.json
uv run python -m app.design_capabilities
```

Конкретные JSON-контракты находятся в `exposlides/design_models.py`,
`app/design_audit.py` и `app/design_image.py`. Входы и результаты этапов сохраняются
в каталоге задания; ключи и `.env` туда не копируются.

После успешной генерации `app.design_main` сохраняет рядом с результатом
`story-provenance.json`: точный настроенный alias, отправляемый в запросе,
каноническую модель, лицензию, размер, роль, версии workflow/реестра и хеш
основного промпта. Шаблоны исправления плана вынесены в `prompts/designer/story_*.md`
и привязаны к роли через `roles.story.prompts` в TOML. Их отдельные хеши входят
в `manifest.versioned_resources`; отсутствие файла выявляется до первого вызова LLM.
URL и ключа в нём нет. Manifest включает эти метаданные и SHA-256 полного
`DesignRequest`, включая наборы данных; для режима `extractive` поле
`story_model` равно `null`. Alias описывает отправленную конфигурацию и
не аттестует реальные веса удалённого сервера.

`app.design_capabilities` печатает только JSON с логическими полями `story`,
`contextual_audit`, `generated_image`. Они означают наличие подходящих настроек и
разрешённого идентификатора модели. Это не сетевой health check и не подтверждение
поддержки изображений конкретным endpoint; URL и ключи в ответ не попадают.

## Необязательные изображения

Штатный маршрут — HF Inference Providers → fal-ai → Z-Image-Turbo. Адаптер
обрабатывает ответ с inline base64-изображением и не скачивает внешние URL.
Для другого явно настроенного endpoint поддержан POST с `inputs` и `parameters`,
возвращающий непосредственно байты PNG/JPEG; произвольные форматы API не поддержаны.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `IMAGE_API_URL` | `https://router.huggingface.co/fal-ai/fal-ai/z-image/turbo` | Штатный маршрут HF/fal |
| `IMAGE_API_KEY` | пусто | Отдельный Bearer-ключ; для штатного HF endpoint используется `LLM_API_KEY`, если отдельный ключ не указан |
| `IMAGE_MODEL` | `Tongyi-MAI/Z-Image-Turbo` | Проверяемая декларация модели endpoint |
| `IMAGE_API_TIMEOUT` | 90 | Таймаут запроса, дополнительно ограничен ролью |

Пример без секретов добавлен в [.env.example](.env.example). URL и ключ нельзя
передать в пользовательском JSON-запросе. Для удалённого endpoint требуется HTTPS;
HTTP разрешён только loopback для локального инференса. Перенаправления отключены.

Запрос содержит `enabled`, `prompt`, `seed`, `width`, `height`, `source_ids`, `palette`.
PNG/JPEG проверяется перед сохранением. Результат содержит статус, путь, SHA-256,
фактический размер, seed, модель, лицензию и версию роли. При ошибке нет подмены
модели и выдуманного изображения. Для подходящих содержательных слайдов создаются
разные иллюстрации, максимум три запроса одновременно и 90 секунд на весь набор
с учётом остатка общего времени задания. Иллюстрация каждого слайда используется
во всех его вариантах, чтобы сравнение верстки сохраняло одинаковое содержание.

Внешний [промпт иллюстратора](prompts/designer/image.md) запрещает текст, числовые
данные и логотипы внутри изображения. Иллюстрация обозначает тему; она не является
свидетельством реального события. Числа и графики формируются нативными объектами
из исходных наборов данных.

## Ресурсы и подтверждение работы

При API-инференсе локальная видеокарта не нужна. Репозиторий не устанавливает
PyTorch, Diffusers или сервер весов и не содержит проверенного локального GPU
развёртывания. Для собственной установки требования зависят от точности весов,
контекста, KV-cache, изображений и разгрузки на CPU; готовый VRAM-профиль проекта
пока не измерен.

Промпты находятся в `prompts/designer/*.md`, роли — в `agents/designer.toml`, модели —
в `config/models.toml`, навыки и пороги аудита — в `config/skills.toml`. Функция
`audit_rules()` реально читает пороги плотности и контраста из этого файла.
Конфиги моделей и ролей загружаются entry points; новый workflow
отклоняет неподтверждённые alias и несовместимые лицензии/размеры из реестра.
Manifest задания автоматически сохраняет хеши `config/*.toml`, `agents/*.toml`
и внешних промптов. API-провайдер не обязан давать
побитовую воспроизводимость даже при одинаковой конфигурации; seed изображения
также не является такой гарантией для разных реализаций инференса.

Новые адаптеры проверены офлайн с fake LLM и mock HTTP: структура запросов,
ограниченные повторы, таймауты, отказ авторизации, неподдерживаемые модели,
обработка изображений и отсутствие утечки ключей. HF/fal Z-Image-Turbo проверялся
реальным запросом; серверный прогон контекстуального аудита описан в
[отчёте проверки workflow](deploy/alex-cloud/WORKFLOW-2026-09-29.md).
**Живой вызов VK и FLUX.1-schnell в этом workflow не подтверждены.**
Исторические замеры другого pipeline/провайдера не доказывают скорость и качество
нового workflow. Перед демонстрацией необходим зафиксированный прогон на
разрешённом endpoint с сохранением manifest, времени, результатов и audit report.

### Изображения

- Модель: [Tongyi-MAI/Z-Image-Turbo](https://huggingface.co/Tongyi-MAI/Z-Image-Turbo).
- Открытые веса; лицензия Apache-2.0 по карточке автора.
- Заявленный размер генеративной модели — 6B; вспомогательные энкодеры не следует
  смешивать с этой цифрой. Лимит image-моделей в специальном пункте ТЗ — 20B,
  общий предел — 35B. Выбран основной генератор существенно ниже специального предела.
- Инференс: HF Inference Providers → fal-ai; модель провайдера `fal-ai/z-image/turbo`.
- Фиксированный маршрут: `https://router.huggingface.co/fal-ai/fal-ai/z-image/turbo`.
- Используется существующий `LLM_API_KEY`. Ключ не отправляется напрямую fal или CDN.
- 8 шагов, одна картинка на запрос, safety checker включён, платное расширение
  промпта выключено. Ответ запрашивается как inline PNG (`sync_mode=true`).
- Разрешение запроса: длинная сторона 1024 px, короткая от 256 px, кратно 32.
  Итог обрезается по центру до точных пропорций рамки. Внешние URL из ответа не скачиваются.
- Локальная GPU не нужна. Зависимости: существующие httpx, python-pptx, Pillow.
  Pillow входит в зависимости python-pptx; новые пакеты не добавлены.
- Два параллельных запроса, максимум 20 областей и 120 секунд на этап по умолчанию.
- Ошибки доступа, оплаты, транспорта, фильтрации и повреждённые изображения
  останавливают публикацию; частичный результат не выдаётся как готовый.
- Картинка не должна служить источником фактов. Текст, цифры и диаграммы остаются
  отдельными объектами презентации. Семантическое соответствие не гарантируется
  структурной проверкой PPTX.

Контекст хранится отдельно в `exposlides/prompts/slide_image.md`, инструкции подготовки
визуального сюжета — в `exposlides/prompts/image_scene.md`. Для каждой области сначала
вызывается `LLM_FAST_MODEL` с JSON Schema, затем Z-Image получает только описание сцены.
Ошибочный ответ этого LLM-запроса останавливает генерацию до вызова image API.
`image_report.json` фиксирует фактически применённую модель и изменённые области.
API обслуживает модель провайдера без закрепления ревизии весов: seed помогает
повторяемости, но не гарантирует одинаковые пиксели после обновлений провайдера.

Для финального конкурсного профиля требуется инференс VK. Использование HF/fal
само по себе не доказывает выполнение этого требования; размещение image-модели
для финала нужно согласовать отдельно.

Источники API, проверенные 28 сентября 2026:

- [Hugging Face: text-to-image](https://huggingface.co/docs/inference-providers/tasks/text-to-image).
- [fal: схема Z-Image-Turbo](https://fal.ai/models/fal-ai/z-image/turbo/api).
- [HF: адаптер fal](https://github.com/huggingface/huggingface_hub/blob/main/src/huggingface_hub/inference/_providers/fal_ai.py).

Автоматические проверки: `uv run pytest tests/test_images.py tests/test_cli.py
tests/test_end_to_end.py tests/test_pptx_builder.py tests/test_web.py`.
Все API в автоматических тестах подменены; такие тесты не доказывают реальный доступ
к платному провайдеру или время генерации на его оборудовании.
